# MGU Browser — 简体中文说明

翻译者：抖音：小白科技杂物社 · BiliBili：小白151 · GitHub：JackieZ123430。

这是面向 BMW MGU / iDrive 7 的实验性原生浏览器界面，使用独立的 Chromium 进程，并提供用于开发的本地 SDK 应用模拟器。
0.16.0 版本发布了包含前端、原生运行时和私有 Chromium 引擎的 **ID7/x86_64 实验性 Store 目录**。
在 Store 中添加 GitHub 源 `pllanaio/mgu-browser`，并选择 **Releases**，即可安装完整组件并获取更新。
已有的 `main` 源需要切换到 Releases 才能获得这些二进制包。项目自身代码采用 MIT 许可证。

**BMW AudioManager/SmartX 音频输出已实现，但此版本仍待实车验证是否能听到声音。受保护的流媒体需要单独提供已获授权的 CDM。项目不分发 Widevine 二进制或 BMW SDK，也尚未确认服务商内容能否播放。**
参见[安装、依赖与回退说明](docs/MGU_STORE.md)。

[完整德文 README](README.de.md) 提供功能与验证边界的详细说明。下文完整翻译英文 README；保留原文历史版本号及各阶段验证状态。

## 简体中文界面

原生菜单跟随车辆系统语言。`zh-CN`、`zh-SG`、`zh-Hans`、`zh-Hans-CN` 和未细分的 `zh` 使用简体中文；显式的繁体中文语言标记继续回退到英文。
日期输入格式、网址和未收录的网页文字保留原值。屏幕键盘仍使用现有拉丁字母布局，本次翻译没有添加拼音输入法。

原生菜单使用较清晰的 CJK 子集图集；另外提供覆盖 GB2312 中文字的标题备用图集，例如“百度热搜”。它不覆盖全部 Unicode 中日韩字符，两份图集均满足渲染器的纹理尺寸限制。
网页由 Chromium 单独绘制。运行时现在打包完整的公共 Noto Sans SC 字体，保留 OFL 许可、来源和校验值，并将引擎原有字体配置作为后备。
这样可保持不可变的 0.1.0 引擎不变；需要同时更新前端和运行时，才能获得标题与网页两部分的修复。
真机检查与本地界面测试分别记录，本次修改没有增加拼音输入法。

## 0.16.0 的桌面浏览器功能

请将 **Browser 和 Browser Runtime 同时更新至 0.16.0**；Engine 保持 **0.1.0**。
Chromium 现在通过内置的 Ozone 离屏显示运行普通浏览器。原生 User-Agent 和 Client Hints 保持不变，反映实际引擎身份。
WebGL 使用现有的软件渲染器。`navigator.webdriver` 仍为真；这不保证消除 CAPTCHA，也不保证受保护的服务内容可以播放。

| 功能 | 已实现的行为与边界 |
| --- | --- |
| 导航 | HTTP/HTTPS、自定义端口、正常的原生网络处理及后台标签页；证书验证保持启用。 |
| 输入 | 原生表单控件、日期/时间、多行文字、修饰键、选择、复制/粘贴、拖动及滚动；大文本按受限大小分块传输。 |
| 对话框 | 警告、确认、文本输入，以及原生 beforeunload 离开/保留提示；取消关闭时保留原标签页。 |
| 身份验证 | 显式回复原生 HTTP Basic/Digest 认证请求，绑定来源、认证域及当前标签页/框架；保留 Chromium 对跨站认证提示的策略。 |
| 页内查找 | 支持文档、Shadow Root 及所属框架的查找、上一个/下一个匹配和区分大小写，保留已有文字选择。 |
| 缩放 | Chromium 原生 100/125/150% 缩放，保持物理图像分辨率，并同步调整指针命中和滚动坐标，也适用于所属的跨站框架。 |
| 文件 | 显示下载列表，并通过已认证的手机连接传送；经明确确认后，将手机上传的文件以流式方式交给指定网页的文件选择框，也支持跨站框架。不能任意访问车机文件路径。 |
| 权限 | 根据 Chromium 原生权限状态，按网站/框架明确决定是否授权；不会凭空提供缺失的车载设备。 |
| 持久化 | 加密保存 Cookie 和网站存储；已测试 localStorage、IndexedDB、CacheStorage 和 Service Worker 注册。可恢复最多八个 GET 标签页网址及活动标签页。 |
| 媒体 | 保留原生 JPEG、全屏、PCM 节奏和控制器功能；实际 BMW 声音输出与受保护服务仍需单独验证。 |
| 桌面功能边界 | 没有扩展管理器、打印对话框或通用桌面文件系统界面。恢复标签页不会重建表单值、POST 请求体或 JavaScript 状态。 |

下载文件每个最多保留 32 MiB，总计 64 MiB；上传文件每个最多 16 MiB，暂存总计 32 MiB，同时限制文件数量。
已知超限的下载会被取消，并通过磁盘与进度检查约束保留量；两次检查之间可能短暂超限。
文件保存在私有持久数据目录，通过配对的本地手机服务传输。

工作文件系统仍为 384 MiB。普通加密快照限额为 64 MiB。
写入进程停止后，引擎崩溃或较大的配置数据采用限额 192 MiB 的流式加密恢复，并保留上一次正常归档。
超过恢复限额或写入失败时，存储状态会报告失败，保留仍存在的私有工作配置，而不是静默丢弃。
未保存的副本无法保证在后端重启或断电后保留。Chromium 尚未写入文件的数据无法恢复；元数据也占用限额，原子替换暂时需要额外磁盘空间。
参见[测试与边界](docs/TESTING.md)。

## 0.15.0 的 CarLifeMedia、前台与可用资源

后端服务取消自身的 RAM 和任务数限制，提高常规 CPU 及 best-effort I/O 优先级，不设置 CPU 配额或固定 CPU 亲和性。
私有的 384 MiB 文件系统仍限制配置、缓存和临时文件；它不是进程内存限制。物理资源及操作系统限制仍然适用。
没有测量之前，不声称真实车机的运行速度有所提高。

音频源被占用时，Browser 可以接管已核实的 **287 / CarLifeMedia** 源。
它会重新核对每条连接的身份，只断开该源的路由，然后建立自身从 287 到 1024 的连接。
其他音频源和其他程序的 SmartX 锁文件保持不变。释放时只断开新建立并归自身所有的连接；被替换的路由不会自动恢复。

应用通过 SDK 请求原生前台，并要求随后实际观察到可见状态和焦点。仅设置本地焦点标志并不够。
重试和等待都有上限；焦点丢失或回复无效会中止获取。参见[音频行为与限制](docs/AUDIO.md)。

请将 **Browser 和 Browser Runtime 同时更新至 0.15.0**；Engine 保持 **0.1.0**。
包含 0.14.0 的视频时序、全屏及控制器改进。真实车机扬声器和固件焦点仍需实车测试。

Chromium 自行决定渲染进程数量，不再采用之前固定的四进程上限。
User-Agent 和 Client Hints 一致报告实际 Chromium/Linux 身份。
Cookie 检查点现在包含标志及分区范围；自建测试中的授权同意 Cookie，以及 Secure/HttpOnly/限定主机 Cookie，在强制终止引擎后仍然保留。

媒体状态的被动读取现已覆盖封闭 Shadow DOM 播放器。
自建的类 Disney 测试页面产生了实际非黑画面及 PCM 音频，静音、零音量、暂停、结束、导航及关闭标签页都会释放音频路由。
状态未知时，仅允许保留已有路由最多四秒，不能获取新路由。
后端断开会释放音频并清除冻结的画面；恢复就绪后，可见且获得焦点的活动应用会重新加载网址或主页。

Netflix/Disney 公共页面已加载。保留的示例邮箱在新旧 UA 下均可继续，因此未复现已报告的通用账号错误，也未确认其已修复。
`/login` 仍先要求邮箱；DOM 中隐藏的密码节点不等于直接密码登录表单。
统一 UA 后，真实 Google 搜索仍返回 HTTP 429 及网络流量/CAPTCHA 页面；测试没有操作 CAPTCHA。
这些要求由 Google 服务端控制；Browser 无法保证消除，也不会自动解答验证。
参见[测试证据与边界](docs/TESTING.md)。

## 0.14.0 的视频时序与全屏

音频桥接现在按所需实时速率接收完整 PCM 块。
媒体探测可找到大型网页模板后面的播放器，全屏保留网站的嵌套布局，渲染反压会在解码前丢弃过时帧。

快速旋转输入合并处理，不额外增加防抖等待；按压会排在此前的旋转步进之后。
合并后的旋转任务最多包含 64 个步进，待处理队列最多 32 个任务，包含按压屏障。
超量或过时的导航输入会取消，不会完整缓存无限输入。

在引擎相同、只修改原生音频辅助程序的独立测试中，2.002 秒内媒体时钟推进从 1.430 秒变为 1.996 秒，交付帧数从 43 变为 60。
另一个人为施加 70% 消费端压力的测试保持交付 89 帧，Node CPU 时间从 389 毫秒降至 252 毫秒。
这些只是限定条件下的本地对比，并非对所有网站或 MGU 帧率的承诺。
参见[测试证据与边界](docs/TESTING.md)。

请将 **Browser 和 Browser Runtime 同时更新至 0.15.0**；Engine 保持 **0.1.0**。
包含启动修复、迁移、iDrive 及手机遥控功能。在该测试环境中，YouTube 在线测试被代理的 HTTP 403 阻止。
真实 BMW 声音及受保护服务播放仍需单独验证。

## 0.13.3 的启动修复

0.13.0–0.13.2 挂载了 384 MiB 工作文件系统，但降权后仍拒绝超过 128 MiB 的配置。
后端在打开 socket 前以状态码 125 退出。现在挂载与校验共用一个限额。
将 Browser 和 Runtime 更新至 0.15.0，也能在当前启动注册允许的情况下恢复已停止的服务；否则 Store 会要求重启。
引擎仍为 0.1.0。就绪判断现要求收到真实的后端通知。

## 流媒体状态

官方桌面 Chrome 搭配自身未修改的 Widevine CDM，已在独立本地会话中播放获授权的公开 Shaka/Sintel 加密测试流。
这不代表已认证任何订阅服务或真实 MGU 的播放能力。
目前 Netflix 和 Disney 公共页面可以加载，但这不是受保护内容播放或已认证账号的验证结果。
已报告的 Netflix 通用错误仍未解决；公开的合成邮箱测试在两种 UA 下都能继续。
早前 Disney 登录/播放的观察结果属于历史笔记本测试。
自建封闭 Shadow DOM 播放器的音频探测问题已在本地修复，并用实际 PCM、静音/暂停/结束检查；这不是服务商播放验证。
YouTube、Prime Video、Paramount+ 及可听见的车辆声音均需单独验证。

后端已启用媒体。早期私有构建曾在作者的 MGU 上渲染静音测试视频；新的打包方案仍需硬件验证。
Chromium 不提供 CDM。0.12.0 加入了独立的 BMW 音频路由。

会话/Cookie 持久化现默认启用，使用受保护的本地网站密钥；HTTP 缓存持久化仍需单独开启。
Cookie 检查点在会话期间运行，保留范围及标志；其他配置存储在正常关闭时保存。
提供分别清除网站数据/缓存/历史记录的功能，以及需要明确操作、绑定来源的密码管理器。
Windows DPAPI 封装电脑端密钥；MGU 后端为独立密码库提供可移植主密码模式，使用 PBKDF2-SHA256 和 AES-256-GCM。
两者使用相同的存储格式和浏览器代码。真实 MGU 的验证仍待完成。
最后一次 Cookie 检查点或配置快照之后的修改仍可能丢失；强制结束引擎的测试不等于真实断电验证。
优先使用网站自身的视频控件，原生控件仅用作后备。

项目不包含专有 SDK 文件、凭据、车辆数据、固件转储或 CDM。
原始代码采用 MIT 许可证；依赖项保留各自许可证，并在发布的二进制旁提供匹配的原生源代码归档。
